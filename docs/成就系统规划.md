# 成就系统规划 · 小窝荣誉柜

2026-10-26 · 最初基于 0.17.0 规划，现已在 0.18.0 实现。24 项条件保持本表设计；正常资源验证全部可达，胖橘成就保留「真正击败并获胜」。完成记录、存档机制与验证范围见 [成就与对局续玩](成就与对局续玩.md)。下文保留最初设计依据，基地装饰仍作为后续扩展。

## 设计方向

成就用于教会玩家搭配伙伴、把握整备时机，并给通关后的重玩提供目标。推荐首版 **24 个成就、5 个分类**；多数在正常推进 30 关的过程中获得，少量需要主动尝试战术。

每个成就赠送专属徽章；完成总数解锁称号。奖励不增加攻击、收入、初始猫粮或人口，不锁兵种，避免成就收集改变当前数值平衡。暂不增加成就货币、每日签到、连续登录或重复击杀上万次的目标。

现有六枚章节纪念章纳入荣誉柜，保留选关页上的章节完成标记，视为同一项荣誉。满血三星目前在模拟胜局中十分普遍，不包装为稀有成就；也不设置故意挨打到残血、原地拖满十分钟、禁用大部分兵种等与顺畅节奏冲突的挑战。

## 条件统一口径

1. **累计进度不要求胜利。** 招募种类、枪手伤害、闪避、伞盾减伤等在有效战斗事件发生后计入；失败或主动退出不清除已经获得的累计进度与已解锁成就。重开清空本局上下文，不重放历史事件。
2. **带“并获胜”的条件只在胜利时发放。** 产能点满后退出、整备期间打出伤害后失败，均不发相应成就。可以当场提示“条件已达成，获胜后解锁”，不能提前显示“已解锁”。平局不算胜利。
3. **参战有实际贡献才计数。** 单位实际造成或承受伤害、完成有效治疗，或者支援效果实际影响了一次有效攻击/减伤。奶妈和铃鼓也能计入，纯粹招募后一直待在基地不算。支援者需要保留来源 ID；同种支援刷新不重复计算一次贡献。
4. **有效伤害不含溢出伤害。** 对剩余 10 血目标打出 125，仅记 10。按原有逐次命中判定顺序分配同帧剩余血量，统计不能改变同时伤害、闪避顺序或随机数消耗。
5. **有效减伤以实际保住的血量为准。** 对某次命中记 `min(命中前剩余血量, 减伤前伤害) - min(命中前剩余血量, 减伤后伤害)`；已经闪避或因隐身无效的攻击不计。多个雨伞不叠加，不把同一次保护重复记给多个施法者。计入我方总伞盾贡献，无需把总分重复分摊。
6. **状态与位移必须生效。** 猫砂以实际落点为准，同枚炸弹按敌军 ID 去重；闪避、隐身或当步死亡后不能持续减攻的目标不计。吸盘、拳套以最终实际位移大于零为准；首领位移免疫、边界裁剪后未移动、命中前目标死亡均不计。吸盘只计远程兵种，首领不算。
7. **鼓舞以有效伤害发生时为准。** 发射时有鼓舞、命中时鼓舞已结束的延迟弹道不计此成就；免伤或对空攻击不计。伤害事件需保留发射者兵种；此成就统计受益兵种集合，不统计虚构的“额外伤害”。
8. **整备伤害按命中时间归属。** 对敌基地实际扣血累积到当前整备周期，下一周期从零开始；已经达到 500 后保留本局达标标记。窗口前发射、窗口内命中的弹道计入，窗口内发射、结束后命中的不计。区间边界复用 `reinforcementPhase`，单局结束时再确认胜利。
9. **单位 ID 只在本局有效。** 跨局去重不能只存 `unit.id`；用局内集合去重后增量计入总数，重开清空集合，防止 ID 重置导致漏计。吸盘与拳套分别计数。
10. **时间以模拟时钟为准。** 暂停、切后台和打开暂停菜单不推进任何单局条件；1×/2×速度不改变门槛。开发 QA、自动模拟、注入资源的演示战斗不写正式成就存档。

## 奖励设计

每项成就自动获得对应徽章，无需逐个点“领取”。首页可佩戴一个称号，结算页一并展示；称号只在主动选择后切换。

| 已完成成就数 | 解锁称号 |
|---:|---|
| 6 | 见习守护喵 |
| 12 | 小窝指挥官 |
| 18 | 猫咪战术家 |
| 24 | 传奇冻干守护者 |

称号里程碑不作为额外成就计数，避免“完成全部成就”依赖自身。初始无称号也可正常游玩。

美术采用“小窝贴纸册”：奶油纸底、柔和描边、猫爪印、缝线与小徽章。分类使用颜色加图案区分；已获得上色并显示勾选，未获得保留轮廓、明确条件和进度，不能只靠颜色辨认。

**后续装饰批次**可按相同完成数加入猫爪旗、粮仓彩带、炮座爪印铭牌、金色头像框。装饰需手动装备，不能遮住三阶建筑轮廓、伤损、主炮等级或场上状态。首版先完成徽章与称号，独立装饰避免与统计主流程同时扩张。

## 展示与操作

### 首页荣誉柜

在“开始守护 / 选择关卡”附近新增“成就 · 7/24”入口，保持开始按钮最突出。成就页包含总进度、当前佩戴称号、分类筛选，以及“全部 / 未获得 / 已获得”筛选。

手机采用可滚动的单列卡片；较宽屏幕可两列。每项直接显示名称、条件、进度与奖励，不依赖鼠标悬停。兵种收集可以展开查看缺少的头像。操作热区至少 44px，支持键盘、焦点返回和减少动态。

### 战斗中

即时解锁使用 HUD 内短提示，约 2 秒自动消失，不暂停战斗、不挡招募与技能。首领预警、施法提示优先；安全位置不足时延后到结算。多个成就同时获得合并为“获得 3 项成就”，完整明细在结算与荣誉柜查看，不能连续弹出十几条。

首版不把完整成就列表塞进战场，不额外占用 320px 小屏的长期 HUD 空间。后续若加入追踪，最多追踪一项，放在暂停面板或已有说明区。

### 结算与退出

结算卡展示“本局新成就”及最接近完成的一项进度，最多直接展示两项，其余折叠；仍以“下一关 / 再来一局”为主操作。失败也显示本局已获得的累计成就。退出后已获得项在首页显示一次新徽章标记，打开后清除，不反复红点催促。

## 现有代码接入方案

当前 `Battle` 已持有猫粮、科技、招募/损失数量、能量、隐身/减益与首领状态；缺少长期统计、分兵种有效伤害、保护来源和逐局成就上下文。现有 `effects` 是短期表现数据，不能拿动画或 DOM 显示作为成就依据。

沿用现有 Phaser 与独立模拟结构，分三层：

| 层 | 责任与建议文件 |
|---|---|
| 真实战斗事件 | `simulation.ts` 在成功招募、科技完成、最终命中/治疗/位移、施法成功、单位死亡、结算处提供只读事件；给命中与弹道补足来源 ID/兵种，所有阵营事件携带 side |
| 成就规则 | 新增 `game/achievements.ts` 配置表、`game/achievement-tracker.ts` 局内与累计状态；消费真实事件，返回新解锁 ID。模拟测试可传空观察器 |
| 界面与保存 | 新增 `ui/achievements.ts` 与样式、`game/profile.ts` 读写版本；首页、暂停/结算入口只读规则结果，保存由主界面协调 |

每个事件只消费一次，不依赖 90ms 的 HUD 刷新节奏。不要创建永久增长的全量战斗日志：累计数值与兵种集合进入档案；单位 ID、同枚炸弹命中集合、当前整备窗口等局内集合在死亡/事件完成/重开后释放。成就逻辑不调用战斗随机数、不改变目标选择、不注入猫粮、不更改命中顺序。

多来源状态重叠时需有确定规则：只保留实际生效的保护/鼓舞来源；同效刷新以最终生效那次为准。为“实际参战”归因，不额外叠加保护数值。来源单位已经死亡时仍可通过本局招募记录识别该次有效贡献。

## 存档与兼容

推荐继续使用原键 `paw-pantry-progress-v1`，将数据体升级为 version 3，在同一份档案内保存主线、经典成绩和成就。键名中的 v1 保留，数据结构版本由字段判断。

```ts
type ProfileV3 = {
  version: 3;
  campaign: CampaignProgress;
  legacy: CampaignProgress;
  achievements: {
    rulesVersion: 1;
    unlocked: Record<string, {
      unlockedAt: number; // 本地记录时间，不参与战斗条件判定
      source: 'play' | 'migration';
    }>;
    stats: AchievementTotals; // 白名单、非负有限值；种类用稳定 ID 数组
    equippedTitle: string | null;
    unseenIds: string[];
  };
};
```

`CampaignProgress` 为示意复用现有类型，序列化时分别校验主线与经典关卡 ID。最重要的兼容点：**当前 `readProgress()` 仅特殊识别 version 2**，不能只把保存版本改为 3；需同时引入统一档案读取器，并迁移所有原有 `serializeProgress()` 写入点，否则会丢主线或覆盖成就字段。

迁移规则：

- 兼容无 version 的经典三关档案、version 2 主线档案以及 version 3 新档案。旧三星标记、最快时间、顺序解锁保持原语义。
- 旧主线已完整通关的章节补发对应 6 类旅程徽章，来源标记为 migration；解锁时间用迁移记录时间，不冒充当年的真实完成时间。经典三关记录不能替代新主线章节。
- 不推断旧对局的枪手伤害、产能等级、招募种类、首领击败或整备推进数据。存档没有这些事实，相关进度从上线后开始。
- 旧玩家一次补发多项只展示汇总，不逐条播放庆祝；按已获得总数计算称号解锁。
- 非法数值/重复 ID/未知成就 ID 做白名单过滤；未知未来档案版本不得当空存档覆盖，保留原始数据并提示版本问题。

继续使用现有 `createProgressStore`，支持浏览器本地存储与小工具原生存储。由统一保存协调器提交 **完整档案快照**，沿用串行写入与失败提示；战役胜利、成就解锁与称号变更都不能继续各自写只含部分字段的对象。

累计进度实时进入内存，短时间合并写入；关键解锁、结算、主动退出、装备称号时立即提交。不能每次攻击都写平台存储。相同完整快照重试不会重复增加计数，重复渲染结算页也不能重复发奖。不要依赖关闭页面时的异步写入保证保存；写入失败明确显示“本次进度暂未保存”。本地浏览器之间不自动同步。

## 实施顺序与验收

**第一步：规则与档案。** 先实现 24 项配置、事件统计、版本迁移、幂等解锁和保存，再接最简进度展示。补齐有效伤害、来源归因和单局窗口统计，避免先做漂亮界面却无法准确判定。

**第二步：荣誉柜。** 接入徽章、四档称号、首页入口、结算展示与低干扰提示，补发已有章节成绩；完成手机与横屏布局。

**第三步：门槛校准。** 以真实资源验证每项可达性，尤其是单弹命中三敌、同一隐身刺客摸到基地、满产能胜利、整备 500 伤害与击败首领再获胜。沿用固定策略作为统计样本，另加可复跑的正常资源定向战术；分别记录，不能把注入资源的定位夹具当作可达性证据。根据结果调整门槛，不为了成就增强兵种。

主要验收点：

- 旧存档迁移后 30 关成绩、经典记录、最快时间与顺序解锁不丢；后续保存不擦除成就。
- 敌方动作不计入我方成就；主炮与我方单位的伤害来源区分正确；同一攻击/死亡/结算只计一次。
